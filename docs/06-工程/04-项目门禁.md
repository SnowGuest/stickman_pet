# 项目门禁

> 上级：[文档中心](../README.md) · 领域：工程
> 契约入口：[AGENTS.md](../../AGENTS.md) · 自动检查：[tools/gate.ps1](../../tools/gate.ps1)
> 目标：让任何新会话/新 agent 在不了解上下文的情况下，也不会把工程带偏。

---

## 1. 为什么需要门禁

这个项目的特点是：

- 单人 + 多会话/多 agent 协作，上下文容易丢失；
- 桌宠依赖大量"看不见的约束"（透明窗口、1:1 坐标、抓取坐标系、发布排除）；
- 一旦发布包混入 `addons/godot_ai` 或 `_mcp_game_helper`，调试通道会进入用户机器；
- 文档与代码分离，容易出现"文档一套、代码一套"。

门禁不是为了阻止变化，而是把**不可协商的底线**变成可执行检查。

---

## 2. 三层结构

| 层 | 载体 | 作用 | 能否绕过 |
|---|---|---|---|
| 契约层 | [AGENTS.md](../../AGENTS.md) | 说明必须读什么、哪些不能做 | 不能 |
| 自动层 | [tools/gate.ps1](../../tools/gate.ps1) | 静态检查 + 可选 Godot/发布校验 | 不能（CI/钩子会重跑） |
| 强制层 | `.githooks/pre-commit`、`.github/workflows/gate.yml` | 提交前、推送后自动执行 | 不能（禁止 `--no-verify`） |

---

## 3. 检查项

### 3.1 致命项（失败即拒绝）

| 类别 | 检查 |
|---|---|
| 必需文件 | README/AGENTS/CONTRIBUTING/CHANGELOG/LICENSE、全部领域文档、PR 模板、测试入口、字体与许可证、主场景、发布脚本 |
| 文档链接 | 所有相对 `.md` 链接必须能解析 |
| 代码块 | Markdown 的 ``` 必须成对 |
| 工程设置 | 主场景存在、版本号语义化、stretch 非 `canvas_items`、透明/无边框/置顶/透明背景为 true、主题存在 |
| 发布规则 | `export_presets.cfg` 排除 `addons/godot_ai`；`build_release.ps1` 含 helper 剥离逻辑 |
| Git 卫生 | 不跟踪 `.godot/`、`build/`、`export/`、`*.exe/pck/log/tmp`、密钥、`export_credentials.cfg` |
| 文本规范 | `.editorconfig` 为 UTF-8；代码/配置无行尾空白；GDScript 行宽 ≤ 100 |
| 变更管理 | `CHANGELOG.md` 含 `## [Unreleased]`；`.gitattributes` 含 `* text=auto` |
| 文档契约 | README/docs README 链接门禁；路线图有"当前状态"；appendix 版本为 v1.13 |

### 3.2 警告项（不阻断，但需处理）

| 检查 | 说明 |
|---|---|
| 未安装本地钩子 | 运行 `tools/install_hooks.ps1` |
| GDScript 缺 `.uid` | 用编辑器保存一次，提交 `.uid` |
| `-Full` 找不到 Godot | 跳过导入/测试，不降低其他检查 |
| 测试只有占位 | `tests/run_tests.gd` 暂未覆盖真实用例 |

### 3.3 可选深度检查

| 参数 | 内容 | 何时用 |
|---|---|---|
| `-Full` | Godot `--headless --import`；有测试则跑测试 | 里程碑、合并前 |
| `-ReleaseCheck` | 生成 `build/staging`，确认无 helper/addon/tests/OFL 缺失 | 发布前、改动构建脚本后 |
| `-Full -ReleaseCheck` | 全部 | 发布候选 |

## 4. 运行

```powershell
# 快速（默认，秒级）
powershell -NoProfile -ExecutionPolicy Bypass -File tools\gate.ps1

# 含 Godot 导入/测试
powershell -NoProfile -ExecutionPolicy Bypass -File tools\gate.ps1 -Full

# 含发布 staging 校验
powershell -NoProfile -ExecutionPolicy Bypass -File tools\gate.ps1 -ReleaseCheck

# 全部
powershell -NoProfile -ExecutionPolicy Bypass -File tools\gate.ps1 -Full -ReleaseCheck
```

退出码：`0` 通过，`1` 失败。CI 以退出码为准。

---

## 5. Git 钩子

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools\install_hooks.ps1
```

安装后：

- `pre-commit`：运行 `tools/gate.ps1`，失败阻止提交。
- `commit-msg`：校验 Conventional Commits。

钩子只调用脚本，不复制逻辑；修改检查规则只改 `gate.ps1`。

---

## 6. CI

`.github/workflows/gate.yml` 在 push/PR 时运行快速门禁。
后续接入 Godot 后，可在同一 workflow 增加 `-Full` job（下载 4.7.2 + 导入 + 测试）。

CI 失败时：

1. 本地复现 `tools\gate.ps1`；
2. 修复根因；
3. 不允许通过改 CI 脚本"跳过"检查。

---

## 7. 绕过政策

**不存在"临时绕过"通道。**

- 禁止 `git commit --no-verify`。
- 禁止注释掉检查、把 Fatal 改成 Warn、在 CI 里 `exit 0`。
- 环境导致无法运行时（如无 Godot），只允许**跳过可选深度检查**，静态检查必须通过。
- 如认为某条检查本身错误，走变更流程：改本文 + 改脚本 + 说明原因，而不是单次绕过。

---

## 8. 如何新增检查

1. 在 `tools/gate.ps1` 中新增检查段，使用 `Fail`/`Warn`。
2. 在本文"检查项"表登记，说明原因与修复方式。
3. 本地跑一次全绿；再提交。
4. 若检查依赖新文件，加入 `$RequiredFiles`。

原则：检查必须**确定、快速、可修复**；不要加入依赖网络或用户环境的致命检查。

---

## 9. 当前限制

- 默认不运行 Godot（避免编辑器占用/启动开销）；靠 `-Full` 与 CI 后续补齐。
- 尚未接入 GDScript 静态分析（`gdformat`/`gdlint`），后续可加。
- 真实导出依赖 4.7.2 导出模板；当前只验证到 staging。
- `-ReleaseCheck` 会复制约 17MB 字体，耗时数秒，属预期。

## 11. 行业参考

门禁不是自创的，主要对照了：

| 实践 | 来源 | 我们的落地 |
|---|---|---|
| 目录组织、资源/场景/脚本分放 | Godot 官方 Project organization | `scenes/`、`scripts/`、`assets/`、`tests/` |
| 忽略 `.godot/`、构建物、凭据；`export_presets.cfg` 入库 | Godot 官方 Version control + godot-ci | `.gitignore` + 门禁 git 卫生 + 发布预设 |
| snake_case/PascalCase、Tab、100 列、静态类型 | Godot GDScript style guide | AGENTS + `.editorconfig` + 门禁文本检查 |
| gdformat/gdlint、去尾随空格、单一主题 PR | Pixelorama CONTRIBUTING | 规范 + PR 模板 + 后续接入 gdformat |
| CI 测试、并发取消、超时 | gdUnit4 CI | `.github/workflows/gate.yml` |
| SemVer + CHANGELOG | 成熟项目通用 | `CHANGELOG.md` + `config/version` |

完整对照、取舍原因与未采用项见 [05-行业实践对照](05-行业实践对照.md)。
