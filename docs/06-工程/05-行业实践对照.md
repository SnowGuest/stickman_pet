## 3. 采用 / 不采用

### 3.1 直接采用

1. **单一主题 PR + 检查清单**：来自 Pixelorama；降低 review 与回滚成本。
2. **`export_presets.cfg` 入库、`export_credentials.cfg` 忽略**：来自 godot-ci 与官方文档；否则 CI 无法导出。
3. **`.editorconfig` + 去尾随空格**：来自 Pixelorama 与官方风格指南。
4. **CI 并发取消 + 超时 + 最小权限**：来自 gdUnit4 示例。
5. **`CHANGELOG.md` + SemVer**：成熟项目通用。
6. **Git 卫生检查**：来自官方 `.gitignore` 与版本控制文档。

### 3.2 有取舍

| 项 | 成熟做法 | 我们的取舍 | 原因 |
|---|---|---|---|
| 测试框架 | 直接引入 gdUnit4/GUT | 先用自研 `run_tests.gd` 占位 | 目前零测试；避免为 0 个用例引入插件与学习成本 |
| Git LFS | 所有大二进制走 LFS | 字体暂常规入库 | 17MB 在 GitHub 限制内；迁移会改写历史，等下次大资源再统一 |
| AI 贡献 | Pixelorama 明确禁止 | 允许，但要求披露与人工复核 | 本项目本身就是 AI 辅助开发；用门禁与人工验收替代"一刀切" |
| 代码格式化 | gdformat 强制 | 先写入规范，脚本出现后接入 | 当前只有占位脚本 |
| 目录名 | 官方示例常用 `src/` | 用 `scripts/` | 与 Godot 资源类型对应，团队更直观 |

### 3.3 未采用（明确记录）

- `CODE_OF_CONDUCT.md`：单人项目，暂无社区治理需求。
- 多语言 CI 矩阵：只做 Windows，避免虚假覆盖。
- 自动发布到 itch.io/Steam：v1 只做绿色版。

## 5. 后续校准

每次发布前复核一次：

- 新增检查是否与官方/成熟项目一致；
- 是否有"只在我们项目成立"的特例，需写原因；
- 未采用项是否仍成立（例如测试框架、LFS）。

> 外部文档只作为参考，不构成约束；与本项目 ADR 冲突时，以本项目文档为准并记录差异。
