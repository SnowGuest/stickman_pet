## 4. 文档契约

每份子系统文档必须包含以下小节（缺一不可）：

| 小节 | 内容 |
|---|---|
| 职责与边界 | 这个模块做什么、不做什么、依赖谁 |
| 输入/输出 | 数据结构、信号、调用时序 |
| 实现 | 算法、公式、关键代码、参数 |
| 失败模式 | 崩溃/抖动/穿透失效等，以及降级策略 |
| 验收 | 可执行的检查项（单测或手动步骤） |

**代码约定**：文档中的代码是"契约级示意"，允许实现时优化性能与拆分函数，但**不得改变接口语义、单位、坐标系与信号契约**。

---

## 5. 变更规则

- 架构级改动：先改 `01-总览/02` 的 ADR，再改代码。
- 范围/排期改动：改 `00-项目/02` 的变更记录，并同步目标文档。
- ADR 只增不改；被推翻的标 `Superseded by ADR-xx`。
- 参数默认值只在领域文档的参数表维护，代码常量必须对应。
- 每次发布在 `appendix/01` 登记文档版本。

## 6. 术语速查

完整表见 `appendix/01-术语与API.md`。最常用的六个：

| 术语 | 含义 |
|---|---|
| Rig | 骨骼数据 + 求解的统称 |
| Pose | 根位置 + 每骨相对角 + 每关节世界坐标 |
| PBD | Position-Based Dynamics，位置约束求解 |
| Tone | 肌肉张力，关节回到动画目标角的弹簧刚度 |
| w_sim | 物理权重，0=纯动画，1=纯布娃娃 |
| Hull | 凸包，用于鼠标穿透区域 |
