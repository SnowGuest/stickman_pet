## 3. 当前在哪一步

**当前阶段：P0 工程基线（收尾）**

已完成：

- 分级文档体系与项目门禁（AGENTS / gate / Git 钩子 / CI workflow）
- git 仓库初始化、远端合并（`origin/main`）
- `project.godot` 基线：透明、无边框、置顶、1:1 坐标、主场景、版本号
- 中文字体 Noto Sans SC + 全局 Theme（已验证无方框）
- 发布脚本与 Windows 导出预设（staging 校验通过）
- 本地 `gate -Full`（Godot 导入 + 测试入口）通过

未完成：

- 导出模板未安装，真实 exe 尚未产出
- 远端 push 受 GitHub 认证阻塞，CI 尚未在远端实际运行
- 游戏逻辑（窗口外壳、骨骼、物理）尚未开始

**下一步：P1 / M0 窗口外壳**
先实现 `DesktopShell`、动态穿透、单实例与坐标转换，再进入 `RigDefinition` 与线条渲染。

**并行轨道 A：AI 控制桥接**
协议与拓扑已定（Godot 做 WS Server、Go 做 Client、高层意图）；等模型格式确认后，可与 P3/P4 并行开发。
表演层（FaceRig/Acting/Reaction）标记为后置，不阻塞 v1.0。

## 4. 阶段依赖

```
P0 工程基线
   │
   ▼
P1 最小可视（M0 窗口 + M1 骨骼/渲染）
   │
   ▼
P2 动画（M2）
   │
   ▼
P3 物理与抓取（M3）  ← 关键路径，手感调参
   │
   ▼
P4 行为与表情（M4）
   │
   ├──► 轨道 A：AI 控制桥接（可与 P3/P4 并行）
   │
   ▼
P5 2.5D 与 3D 物品（M5）
   │
   ▼
P6 稳定与发布（M6）
```

依赖原则：

- P1 的坐标/穿透错误会污染后续所有交互，M0 必须先验收。
- P3 的调试面板必须在调参前完成，否则是盲调。
- P4 的动画质量依赖 P2 的剪辑；P5 的物品层级依赖 P3/P4 的姿态与状态。

---

## 5. 完成定义

每个阶段完成必须同时满足：

1. 需求表中的验收项全部通过；
2. `tools/gate.ps1` 通过；
3. 文档同步（参数、接口、进度）；
4. 版本迭代记录已更新；
5. 有可复现的验收记录（命令/截图/日志）。

---

## 6. 维护方式

- 每完成一项需求，更新对应阶段文档的状态与 `02-路线图与进度.md` 的看板。
- 阶段状态变化时同步更新本页总览与版本迭代目录。
- 范围变更走 [项目目标](../01-项目目标.md) 第 8 章流程。
