---

## 1. 愿景

做一只**真正住在桌面上的火柴人**：不是会播动画的挂件，而是一个能被抓住、被拎起、被扔出去，身体会像有重量一样晃动，落地后会自己爬起来的角色。它不打扰工作，但你看它一眼就会想戳它一下。

---

## 2. 项目目标

| 编号 | 目标 | 说明 |
|---|---|---|
| G1 | **手感可信** | 抓取、下垂、摆动、投掷、落地、恢复形成闭环，看起来"有重量、有肌肉" |
| G2 | **桌面融合** | 真透明、真置顶、不抢焦点、空白穿透，像长在桌面上 |
| G3 | **长期可维护** | 数据驱动（骨骼/动画/配置），加内容不改核心代码 |
| G4 | **可交付** | 能打包成单文件 exe，连续运行 8 小时，可给非开发者使用 |

## 3. 成功定义

### 3.1 MVP（可自用）

- 窗口透明置顶、可穿透。
- 火柴人待机、被抓、被扔、爬起。
- 抓腰自然下垂，抓头倒挂。
- 配置可保存，重启还原。

### 3.2 v1.0（可交付）

- MVP + 2.5D 分层 + 姿态/音效。
- 多屏/DPI 自适应，右键菜单完整。
- 8h 稳定性、安装包/绿色版、发布检查清单通过。

### 3.3 明确失败

- 抓取像"拖图片"，没有重量感。
- 摆动抖成弹簧，或永远不衰减。
- 空白处点击被吞，影响正常办公。
- 只能在自己的机器上跑。

## 4. 范围

| 范围内 | 范围外 |
|---|---|
| 单只火柴人 | 多角色同屏 |
| 鼠标交互 | 键盘/手柄/语音 |

范围变更必须走第 8 章流程。

## 5. 约束

| 约束 | 内容 | 影响 |
|---|---|---|
| 人力 | 1 名开发者 + AI 辅助 | 总工期按"人日"估算，需留 30% 缓冲 |
| 时间 | 业余投入，按 4h/天折算 | 26 人日 ≈ 6–7 周 |
| 预算 | 0（免费工具、无美术外包） | 程序化绘制 + 原创图标/音效 |
| 平台 | Windows 优先 | 透明/穿透只保证 Windows |
| 引擎 | Godot 4.7.2 固定 | 升级需单独评估（见工程基线） |
| 依赖 | 发布版零外部运行时 | 不能依赖 Python/uvx |

## 7. 关键假设

1. 目标机器支持 per-pixel transparency（Win10 1903+）。
2. 用户接受"全屏透明窗口"的实现方式。
3. GDScript 性能足够（13 骨、14 粒子）。
4. 素材可以原创，不依赖第三方版权资源。
5. 发布形态为绿色版 zip（安装包可选）。

假设失效时，触发风险登记表中的对应条目。

## 8. 目标与范围变更

1. 提出变更：写清"改什么、为什么、影响哪些里程碑"。
2. 评估：工期 ±、风险 ±、是否影响 v1.0 成功定义。
3. 决策：接受 / 推迟到 v1.1 / 拒绝，记录在 [路线图](02-路线图与进度.md) 的变更记录。
4. 同步：更新本文、路线图、相关领域文档与 README 索引。

**冻结期**：M3（物理手感）验收后到 M6 发布前，不再接受新功能，只修 bug 与调参。

## 9. 质量门

每个里程碑必须同时满足：

- 功能：对应场景剧本通过。
- 性能：该阶段预算内（见 [工程文档](../06-工程/02-规范测试与发布.md)）。
- 稳定：无 NaN、无崩溃、无持续报错。
- 文档：接口/参数变更已回写。
- 可回滚：有上一版可运行构建。
