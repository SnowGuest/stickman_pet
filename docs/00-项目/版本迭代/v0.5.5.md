# v0.5.5-ai · AI 控制桥接

> 状态：⬜ 计划中 · 轨道：[A · AI 控制桥接](../路线图/轨道A-AI控制桥接.md) · 发布日期：待定
> 版本号：`0.5.5`（计划，ai 标记）

---

## 1. 迭代说明

在不改变桌宠自主性的前提下，接一个独立的 Go AI 客户端：它内置训练好的模型，通过本机 WebSocket 读取状态、下发高层意图。AI 只是"另一个大脑"，不是桌宠的依赖。

---

## 2. 计划内容

### 新增

- AI 协议 v1：`hello/welcome/state/command/ack/event/ping`；
- Godot `AiBridge`：WS server、token、单客户端、15Hz 状态；
- 命令校验：白名单、范围、TTL、速率、ack 原因；
- 模式仲裁：`MANUAL > REMOTE_AI > AUTONOMOUS`；
- Go 客户端：连接、心跳、重连、协议结构体；
- `Policy` 接口与模型加载（ONNX/TFLite/原生）；
- 推理循环与 JSONL 日志/回放；
- 无桌宠时的状态回放模拟器。

### 变更

- `PetBrain` 增加 `remote` 命令入口与用户抢占；
- 断线后自动回到自主模式；
- 调试面板增加 AI 连接状态。

### 修复

- 网络抖动导致的命令堆积/过期执行。

---

## 3. 验收目标

- [ ] Go 客户端连接/断开/重连 10 次，桌宠状态正常
- [ ] 用户拖拽时 AI 命令被拒绝，松手后可恢复
- [ ] 15Hz 状态 + 30Hz 命令无堆积
- [ ] 非法 JSON/未知动作/超大消息不崩溃
- [ ] 推理 500ms 时不阻塞状态接收
- [ ] 本地日志可回放一次完整交互
- [ ] `gate -Full` 通过
- [ ] 更新本页与 CHANGELOG

---

## 4. 依赖与风险

- 依赖 P1 的输入/状态、P3 的物理、P4 的状态机；
- 可先做协议 + Go 客户端 + 模拟器，不等桌宠完成；
- 风险：模型格式未定 → 先定义 `Policy` 接口，后接具体运行时；
- 风险：延迟 → 高层意图 + TTL；
- 风险：安全 → 仅本机 + token + 白名单。
