# 最终产品定义

> 上级：[文档中心](../README.md) · 同级：[产品与边界](01-产品与边界.md) · [架构与运行时](02-架构与运行时.md)
> 本文回答唯一的问题：**这个项目最终要做成什么样子，才算"像 Alan Becker 的桌面宠物"？**
> 技术方案见领域文档；本文只定义体验、表演与验收。

---

## 1. 一句话

**一段住在 Windows 桌面上的、可以随时伸手打断的无声火柴人短片。**

不是"会播动画的挂件"，也不是"能拖拽的物理模型"。它应该像 Alan Becker 的 *Animator vs. Animation* 里跑出来的一小段：火柴人把桌面当成舞台，把鼠标当成对手/伙伴，用身体和动作节奏演戏，没有对白，但有幽默和情绪。

> **无脸设定**：火柴人没有脸。不绘制五官，也不做面部系统；所有情绪只靠头部朝向、身体姿态、动作节奏、物理反馈和音效表达。

> Alan Becker 自述："I make stick figure animations that take place on a computer desktop screen. There is no dialogue, but a lot of humor and emotion."
> —— 引自 [TV Tropes: Animator vs. Animation](https://tvtropes.org/pmwiki/pmwiki.php/WebAnimation/AnimatorVsAnimation)

## 2. 参考作品拆解

| 参考 | 可借鉴 | 不照搬 |
|---|---|---|
| **Alan Becker / Animator vs. Animation** | 桌面即舞台；无对白；身体演戏；弹性动作；幽默节奏；火柴人与鼠标/窗口的互动 | 具体角色、分镜、台词、音效、画面 |
| **Shimeji**（[VShimeji README](https://github.com/Valkryst/VShimeji)） | 自主游荡、追鼠标、被拖/被扔、沿着窗口边缘活动；XML 配置动作与行为 | 纯贴图帧动画；无骨骼物理 |
| **VPet**（[README](https://github.com/LorisYounger/VPet)） | 摸头、举起、爬墙、大量互动动画；桌宠需要"可玩的小动作"而不只是待机 | 养成/数值/大量 UI；与本项目定位不同 |
| **Desktop Mate**（[Steam](https://store.steampowered.com/app/3301060/Desktop_Mate/)） | 3D 角色桌宠的品类验证；点击/注视互动 | 3D 虚拟形象路线，与本项目 2D 火柴人不同 |

结论：**Shimeji 提供"桌宠行为"的骨架，Alan Becker 提供"表演"的灵魂。** 只做前者会像挂件，只做后者会像播放器；两者叠加才是最终目标。

## 3. "像 Alan Becker" 的六个可验收特征

### 3.1 线条语言

- 彩色、粗细基本一致、圆头关节；
- 圆头但**没有五官**；
- 五色参考：`#66CC00`、`#FF6600`、`#33CCFF`、`#CC0000`、`#FFCC00`；默认橙色 + 空心头，其余实心（见 [配色与无脸规范](../04-表现/05-配色与无脸规范.md)）；
- 白色/浅色留白，不靠贴图堆细节；
- 深色壁纸下有白色描边保证可读。

### 3.2 头部朝向与身体语言

- 靠头部转向、抬头/低头表示注意；
- 躯干前倾/后仰、肩膀耸起/塌下表示情绪；
- 挤压/拉伸、手脚跟随、重心变化表达"疼/懵/生气/得意/困"；
- 情绪是姿态与节奏的组合，不是面部参数。

### 3.3 弹性运动

- squash & stretch：落地压扁、起跳拉长；
- 预备动作（anticipation）：抓取/扑向鼠标前先蓄力；
- 跟随与过冲（follow-through / overshoot）：手脚比躯干晚半拍；
- 极限帧与 smear：快速动作可夸张，不追求物理精确。

### 3.4 喜剧节奏

- **停顿**：被戳后先定住 0.1s，再爆发出反应；
- **take**：定住、后仰、身体炸开；
- **反差**：平时瘫着，突然认真；
- **重复与变奏**：同一反应第二次要不一样。

### 3.5 桌面即舞台

- 鼠标是"另一个角色"：会看、会追、会抓、会躲；
- 屏幕边缘/任务栏/窗口边缘是地形；
- 不读取窗口内容，只利用几何边界。

### 3.6 无对白叙事

- 不用文字气泡推动情绪；
- 用姿态、节奏、音效表达"疼/懵/生气/得意/困"；
- 观众能在 15 秒内看懂发生了什么。

## 4. 最终体验剧本

| 编号 | 场景 | 期望反应 | 验收 |
|---|---|---|---|
| A1 | 第一次被注意到 | 待机 → 看向鼠标 → 歪头/招手 | 3s 内建立"它看见你了" |
| A2 | 被戳 | 定住 0.1s → 后仰瞪眼 → 瞪你 → 恢复 | 有明确"被冒犯"的喜剧感 |
| A3 | 抓腰提起 | 腿下垂摆动 → 试图抓住你的手/往上爬 → 失败瘫掉 | 像被拎起的猫，不像布条 |
| A4 | 抓头倒挂 | 手臂下垂晃 → 眩晕星星 → 挣扎 | 颈/肩不反折，有重量 |
| A5 | 甩出去 | 飞出 → 撞边/落地 → 滑行 → 摇头 → 爬起 | 2.5s 内完成，有冲击 |
| A6 | 转圈圈 | 原地转圈 → 晕 → 扶头 → 站直 | 3–5s，不进入永久眩晕 |
| A7 | 桌面边缘 | 探头看任务栏/扒着屏幕边 | 有"探索桌面"的主动行为 |
| A8 | 睡觉/唤醒 | 蜷缩、Zzz；点击惊醒、手忙脚乱 | 睡与醒有反差 |
| A9 | 按住推 | 桌面空白按住，光标变实体，把待机角色推得踉跄 | 推得动，松手不残留 |
| A10 | 快速撞 | 按住左键快速掠过，角色被撞飞/后仰 | 有冲击感，不穿透 |
| A11 | 15 秒短片测试 | 随机录一段交互给陌生人看 | 不看文字能说出情绪与事件 |

## 5. 当前设计缺的"表演层"

现有文档强在物理、渲染、窗口；弱在"演戏"。需要补四块：

| 缺口 | 说明 | 归属阶段 |
|---|---|---|
| **HeadAim** | 头部/躯干朝向光标；无面部 | P4 |
| **ActingLayer** | 预备/缓冲/停顿/过冲/极限帧；在动画剪辑之上叠加表演 | P2 + P4 |
| **ReactionLibrary** | take、后仰、摇头、摊手、眩晕等可组合反应 | P4 |
| **CursorAwareness** | 头部跟随、追鼠标、被抓时抓回、躲鼠标 | P4（依赖平台输入） |
| **Impact FX** | 速度线、尘土、星星、汗滴、冲击帧 | P5 |

> 这些不是"锦上添花"。没有它们，P3 的物理再准也只是"会晃的模型"，不会像 Alan Becker。

## 7. 验收标准

### 7.1 表演验收

- [ ] 15 秒无声录屏，陌生人能说出至少 2 种情绪；
- [ ] 同一"被戳"连续 3 次，反应不完全重复；
- [ ] 抓腰/抓头/抓脚三种姿态，身体语言明显不同；
- [ ] 落地后有"缓冲—摇头—站起"的表演，不是瞬间复位；
- [ ] 待机 10 分钟，至少出现 3 种主动小动作（看鼠标、伸懒腰、扒边）。

### 7.2 技术验收

- [ ] 抓取响应 ≤ 1 帧；
- [ ] 抓腰 0.2s 内下垂，3 周期内摆动衰减；
- [ ] 0 反折、0 NaN、0 穿墙；
- [ ] 逻辑 < 4ms，60fps；
- [ ] 8h 稳定，无内存增长。

### 7.3 "像不像"的主观验收

给 3 个没看过开发文档的人看 15 秒录屏，问两个问题：

1. 这是不是一个火柴人动画里的角色？
2. 它有没有情绪？

两个问题都答"是"，才算通过。

## 8. IP 边界

- 可以借鉴：火柴人风格、桌面舞台、无对白表演、弹性动作、幽默节奏；
- 不可以：复制 Alan Becker 的具体角色、分镜、台词、音效、画面；
- 不使用 "Alan Becker" / "Animator vs. Animation" 作为产品名或宣传背书；
- 所有动画、姿态、音效原创；发布页加非官方声明。

详见 [风险与合规](../00-项目/03-风险与合规.md) 第 2 章。

## 9. 对路线图的影响

> **排期调整（2026-10-19）**：表演层（HeadAim/ActingLayer/ReactionLibrary/Impact FX）后置到 v1.1；v1.0 不强制 15 秒短片验收。当前优先接入独立 Go AI 客户端（[轨道 A](../00-项目/路线图/轨道A-AI控制桥接.md)），表演层保留为最终目标，不删除。

- P2 增加"表演性关键帧"（预备/停顿/过冲），不只做循环剪辑；
- P4 增加 `HeadAim`、`ReactionLibrary`、`CursorAwareness`；
- P5 增加冲击特效与"15 秒短片"验收；
- P6 把"15 秒无声短片"纳入发布验收。

> 结论：技术路线不变；**验收标准从"物理正确"升级为"表演可信"**。物理是手段，短片感才是最终结果。
